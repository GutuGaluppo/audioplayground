# Releasing

## macOS (Developer ID, notarized)

One-time setup (needs a paid Apple Developer account; only a human can do this):

1. Create a **Developer ID Application** certificate and install it in the login keychain.
2. Store notarization credentials:
   `xcrun notarytool store-credentials ap-notary --apple-id <id> --team-id <TEAMID>`
   (an app-specific password, or `--key`/`--key-id`/`--issuer` for an App Store Connect API key).

Each release:

```bash
cmake --preset release && cmake --build --preset release
AP_SIGN_IDENTITY="Developer ID Application: <Name> (<TEAMID>)" AP_NOTARY_PROFILE=ap-notary \
  tools/release/package-macos.sh
```

The script signs with the hardened runtime and the app's entitlements (only
`com.apple.security.device.audio-input`, generated by the JUCE build), verifies the signature,
notarizes, staples the ticket, checks Gatekeeper (`spctl`) and writes
`dist/AudioPlayground-<version>-macos.zip`.

Without the two variables it signs ad hoc and skips notarization: use that to check locally that the
app still runs under the hardened runtime (it does as of Phase 6). Gatekeeper rejects ad-hoc builds
on other Macs.

Before a public release:
- Bump `project(... VERSION)` in `CMakeLists.txt`; the bundle version follows it.
- Settle the bundle id (`AP_BUNDLE_ID`): it is a persistence contract once shipped (settings,
  microphone permission, signing).
- Freeze project schema v1 (ADR-006): from then on every change needs a version bump and a migration.
- Universal builds (Apple silicon + Intel) need `-DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"`; not set
  up or tested yet.
